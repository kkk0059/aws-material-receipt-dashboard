# 物料點收管理看板－介面設計需求架構 V1

## 1. 文件目的

本文件定義「物料點收管理看板」的畫面結構、操作規則、資料呈現方式與驗收標準，作為後續調整前端、改作公司版或交接開發時的共同依據。

本文件關心的是「使用者在畫面上看到什麼、能做什麼、異常要怎麼凸顯」，不取代資料解析、AWS 部署或來源檔格式規格。

相關文件：

- [Canonical_Data_Model_V1.md](Canonical_Data_Model_V1.md)：看板使用的統一資料欄位
- [Source_Document_Access_Design_V1.md](Source_Document_Access_Design_V1.md)：來源文件的受控開啟方式
- [Synthetic_Demo_File_Spec_V1.md](Synthetic_Demo_File_Spec_V1.md)：AWS 專題 Demo 檔規格

## 2. 設計目標與範圍

### 2.1 主要目標

1. 管理者可在同一畫面掌握全部工單與待處理異常
2. 進度、點收結果與資料品質必須分開呈現，避免「100% 完成」掩蓋異常
3. 點選工單後可快速查看原因與來源文件
4. 使用者不必記住新舊版 Excel 的欄位差異；看板只呈現統一判定結果
5. 資料更新後只更新有變化的畫面資料，避免整頁閃爍或重置使用者正在看的工單

### 2.2 使用者與使用情境

| 使用者 | 主要任務 | 介面需求 |
|---|---|---|
| 管理者／點收確認人員 | 找出缺料、數量差異、未完成工單 | 異常篩選、清楚標籤、工單詳情 |
| Demo 報告者 | 產生正常或異常展示檔，證明自動處理 | 僅 AWS 專題版提供 Demo 產檔入口 |
| 後續維護人員 | 判斷資料來自哪裡、是否更新成功 | 資料來源狀態、最後更新時間、可追溯欄位 |

### 2.3 版本邊界

| 項目 | AWS 專題展示版 | 後續正式／公司版 |
|---|---|---|
| 看板查詢、篩選、詳情、來源文件開啟 | 保留 | 保留 |
| Demo 產檔按鈕與情境選擇 | 保留，供報告示範 | 移除或以管理者測試功能隔離 |
| 合成資料標示 | 顯示 `Synthetic Data Only` | 改為實際資料來源／環境標示 |
| 來源文件 | 透過 API 取得短效開啟連結 | 依公司受控資料夾與權限機制實作 |
| 使用者登入與角色權限 | 不在本專題範圍 | 導入前必須補齊 |

## 3. 資訊架構與畫面分區

```text
┌──────────────────────────────────────────────────────────────┐
│ A. 頂端列：系統名稱、資料來源／環境狀態                       │
├──────────────────────────────────────────────────────────────┤
│ B. 總覽區：頁面標題、最後更新、Demo 產檔入口（僅展示版）      │
├──────────────────────────────────────────────────────────────┤
│ C. 摘要卡：總工單、已完成、需要處理、平均完成率               │
├───────────────────────────────────────┬──────────────────────┤
│ D. 工單清單                            │ E. 工單詳情           │
│    搜尋、篩選、表格、選取列            │    進度、異常、來源檔 │
└───────────────────────────────────────┴──────────────────────┘
```

### A. 頂端列

| 元件 | 顯示內容 | 規則 |
|---|---|---|
| 系統識別 | `物料點收管理看板 / Material Receiving Dashboard` | 固定顯示 |
| 環境狀態 | AWS 專題版：`AWS API / Synthetic Data Only`；本機版：`Local API / Synthetic Data Only` | 成功連線為綠點；備援資料或連線異常顯示警示色 |
| 品牌標記 | `M` 圖示 | 白字、深藍綠底，不可因 CSS 繼承而跑位 |

### B. 總覽區

| 元件 | 需求 |
|---|---|
| 主標題 | `工單點收狀態總覽 / Work Order Receiving Overview` |
| 說明文字 | 明確說明「進度與點收結果分開判斷，異常不會被 100% 完成率掩蓋」 |
| 最後更新 | 顯示最新一筆工單的系統處理時間，統一轉為台灣時區 `YYYY-MM-DD HH:mm:ss` |
| Demo 產檔 | 僅 AWS 專題／本機展示模式顯示；正式公司版不可在一般看板保留此按鈕 |

### C. 摘要卡

| 卡片 | 計算／資料來源 | 目的 |
|---|---|---|
| 總工單 | 目前載入工單筆數 | 掌握看板資料量 |
| 點收完成 | `receipt_status = completed` 的筆數 | 顯示無需處理筆數 |
| 需要處理 | `action_required = true` 的筆數 | 優先處理量 |
| 平均完成率 | 全部工單 `completion_rate` 的平均值 | 僅顯示 PN 覆蓋情況，不代表整體無異常 |

> 規則：摘要卡只能提供概覽，不能取代工單清單與異常狀態。特別是「平均完成率高」不得使用綠色或文案暗示「無異常」。

### D. 工單清單

#### 固定欄位

| 欄位 | 顯示內容 | 使用規則 |
|---|---|---|
| 工單號碼 | `work_order`、新／舊版標示 | 點選整列可切換右側詳情 |
| PN 覆蓋率 | 進度條 + `completion_rate` | 僅代表 `received_pn / required_pn` |
| 點收結果 | `receipt_status` 狀態標籤 | 主要異常判斷欄位 |
| 資料品質 | `data_quality_status` | 與點收結果獨立，不能覆蓋或改寫結果 |
| 更新時間 | `last_updated`、是否需要處理 | 顯示為台灣時區 |

#### 搜尋與篩選

| 功能 | 規則 |
|---|---|
| 工單搜尋 | 依工單號碼部分比對，不區分英文大小寫 |
| 全部 | 顯示全部資料 |
| 需要處理 | `action_required = true` |
| 已完成 | `receipt_status = completed` |
| 缺料 | `receipt_status = shortage` |
| 數量差異 | `receipt_status = quantity_difference` |
| 需要複核 | `receipt_status = review_required` |

#### 清單視覺規則

- 被選取的列使用淺藍底色，不只靠滑鼠停留效果
- 狀態採標籤顯示，不可只使用顏色區分
- 點收結果與資料品質要分欄顯示；資料品質缺漏不可以把正常點收結果改成異常
- 搜尋沒有結果時，顯示「找不到符合條件的工單」，不可留下空白表格造成誤解

### E. 工單詳情

| 區塊 | 顯示資料 | 重點規則 |
|---|---|---|
| 標題 | 工單號碼、點收結果 | 狀態標籤與清單一致 |
| PN 點收覆蓋率 | `received_pn / required_pn`、百分比、進度條 | 必須註明這只比較需求 PN 與已有點收紀錄 |
| 六格事實卡 | 需求 PN、已點收 PN、數量差異、缺料數、多給 PN、實點差異 | 與目前異常相關的卡片要凸顯紅底／紅字 |
| 處理說明 | `reason_zh`、`reason_en` | 顯示是否需要處理與原因 |
| 來源文件 | `開啟來源文件` 按鈕 | 只能透過受控 API 取得開啟連結；不可直接拼接內部路徑 |
| 作業資訊 | 作業人員、確認時間 | 缺失時標示「未提供 / Missing」，並以資料品質問題處理 |

## 4. 資料狀態與異常呈現規則

### 4.1 點收結果優先順序

同一工單可能同時有多種問題。看板主要狀態依下列優先順序選出一種最需要處理的結果：

| 優先序 | 狀態 | 顯示文案 | 詳情應凸顯的欄位 |
|---:|---|---|---|
| 1 | `shortage` | 缺料 / Shortage | 缺料數 |
| 2 | `review_required`／`extra_pn` | 需要複核 / Review Required | 多給 PN |
| 3 | `pending` | 尚未完成 / Pending | 已點收 PN；若同時有數量差異，也凸顯數量差異 |
| 4 | `quantity_difference`／`receipt_issue` | 數量差異／點收異常 | 數量差異或實點差異 |
| 5 | `completed` | 點收完成 / Completed | 不凸顯異常卡 |

### 4.2 資料品質規則

| 狀態 | 意義 | 畫面處理 |
|---|---|---|
| `complete` | 需要的歷程欄位完整 | 顯示「完整 / Complete」 |
| `missing_metadata` | 作業人員或確認時間等歷程欄位缺失 | 顯示「資料缺失 / Missing Data」，詳情欄位標紅 |
| `legacy_incomplete` | 舊版歷史資料欄位不完整 | 顯示「歷史資料不完整 / Legacy Incomplete」 |

> 資料品質不是點收異常。它只說明歷程欄位是否完整，不能改變缺料、數量差異或完成的點收判定。

### 4.3 異常訊息原則

1. 先說結論，再說原因，例如「需要處理：尚有需求 PN 未完成點收」
2. 中文為主、英文對照為輔，避免只有英文錯誤碼
3. 來源檔開啟失敗時，明確指出「無法開啟來源文件」與可檢查的服務狀態
4. 損壞 XLSX 不在一般工單清單建立新工單；其處理結果由拒收區與日誌追溯

## 5. 使用流程與互動需求

### 5.1 一般管理者流程

```text
開啟看板
→ 先看「需要處理」摘要卡
→ 點選「需要處理」篩選
→ 選取工單
→ 查看右側原因與紅色凸顯欄位
→ 需要時開啟來源文件
→ 依現場流程處理／回報
```

### 5.2 來源文件開啟

| 步驟 | 需求 |
|---|---|
| 1 | 使用者按「開啟來源文件」 |
| 2 | 前端向專用 API 請求可開啟文件連結 |
| 3 | API 驗證該工單與使用權限後，回傳短時間有效連結或公司內部受控開啟方式 |
| 4 | 交由使用者電腦預設試算表程式開啟，例如 WPS 或 Excel |
| 5 | 前端不得顯示或保存 S3 Object Key、公司共用資料夾完整路徑或雲端憑證 |

### 5.3 資料更新與畫面穩定性

| 情境 | 規則 |
|---|---|
| 初次載入 | 顯示載入中，取得 API 資料成功後更新 |
| AWS 專題版輪詢 | 每 60 秒查詢一次 API，降低 API 呼叫量與成本 |
| 無資料變化 | 不更新 React 狀態、不重繪清單，避免畫面閃爍 |
| 有資料變化 | 更新摘要、清單、最後更新時間；保留原篩選條件 |
| 使用者正在查看某工單 | 若該工單仍存在，維持選取；不可無故跳回第一筆 |
| API 暫時失敗 | 保留最後成功資料，頂端改為「本機備援 / Local Fallback」或明確連線異常狀態 |

### 5.4 AWS 專題展示模式：Demo 產檔

> 此功能僅供展示自動化，不是正式作業功能。公司版預設移除。

| 項目 | 需求 |
|---|---|
| 入口位置 | 右上角「產生 Demo 檔」按鈕，不影響正式看板主結構 |
| 呈現方式 | 點擊後以彈出視窗選擇，不在首頁直接堆放選項 |
| 可選版本 | 新版 / Current、舊版 / Legacy |
| 可選情境 | 正常完成、尚未完成、缺料、數量差異、點收異常、舊版多給 PN、損壞 XLSX |
| 正常檔結果 | 顯示「自動匯入」通知，更新工單清單、詳情與最後更新時間 |
| 損壞檔結果 | 顯示「預期拒收」通知；不增加工單筆數；可至 S3 拒收區與 CloudWatch 日誌確認 |
| 成功提示 | Toast 5 秒後自動消失，不可永久遮擋畫面 |

## 6. 視覺與版面規範

### 6.1 設計原則

- 風格：乾淨、企業內部管理看板，不使用過度裝飾或 AI 感圖形
- 色彩：深藍綠為主色；綠色代表完成；琥珀色代表待複核／尚未完成；紅色代表需要處理
- 語言：中文為主，英文作欄位對照；不可因雙語而把主要資訊縮得難以閱讀
- 字級：標題要明顯大於內文；表格最小字級以一般桌機閱讀為準，不可為塞資料而過度縮小

### 6.2 響應式規則

| 畫面寬度 | 版面行為 |
|---|---|
| 桌機（≥ 980px） | 工單清單與詳情並排；詳情可固定在右側 |
| 平板／小桌機 | 摘要卡可改為 2 欄；詳情改為隨頁面捲動 |
| 手機（≤ 620px） | 摘要卡 2 欄、隱藏非必要的最後更新區域；表格可水平捲動 |

### 6.3 無障礙與防呆

- 狀態不可只靠顏色，必須同時有文字標籤
- 工單列可使用鍵盤 Enter 選取
- 按鈕載入中應停用，避免重複產檔或重複開啟文件
- 空清單、API 失敗、來源文件無法開啟都要有明確文字訊息

## 7. 非功能需求與資料保護

| 類別 | 需求 |
|---|---|
| 效能 | 一般資料量下首次載入與篩選不應卡頓；無變更輪詢不可造成整頁閃爍 |
| 成本 | AWS 版以 60 秒輪詢為預設；未確認有即時推播需求前，不增加 WebSocket 等常駐連線成本 |
| 安全 | 前端不可保存 AWS Credential、資料庫直接連線資訊或來源檔內部位置 |
| 可追溯 | 看板顯示最新狀態；匯入紀錄、損壞檔與拒收日誌由後端保存供追查 |
| 文件相容 | 來源文件開啟應支援使用者 Windows 預設試算表程式，包含 WPS 或 Excel |
| 正式導入前提 | 真實資料串接、帳號登入、角色權限、公司共用資料夾存取與稽核規則需另行確認，不可直接沿用 Demo 設定 |

## 8. 驗收條件

### 8.1 必須通過（Must Have）

- [ ] 可成功載入工單清單、摘要卡與右側詳情
- [ ] 搜尋及六種篩選可正確縮小工單清單
- [ ] 進度、點收結果、資料品質三者分開呈現
- [ ] 缺料、數量差異、已點收 PN 不足、歷程欄位缺失會在正確區塊凸顯
- [ ] 點選工單不會錯置詳情資料
- [ ] 最後更新時間顯示台灣時區且格式正常
- [ ] 無資料變更時，輪詢不造成整頁閃爍
- [ ] 來源文件僅能經專用 API／受控機制開啟，前端不公開內部路徑
- [ ] 損壞檔不會出現在正常工單清單

### 8.2 AWS 專題展示版追加驗收

- [ ] Demo 產檔以彈出視窗操作，不破壞首頁正式版面
- [ ] 可選新版／舊版與各種正常、異常情境
- [ ] 正常 Demo 檔能自動匯入並更新看板
- [ ] 損壞 XLSX 被拒收後，工單總數不增加
- [ ] 成功／送出通知 5 秒後自動消失

### 8.3 正式公司版上線前必須移除或補強

- [ ] 移除一般使用者可見的 Demo 產檔 API 與按鈕
- [ ] 改接公司核准的來源資料夾與受控檔案開啟流程
- [ ] 補上帳號登入、角色權限與操作紀錄
- [ ] 確認真實資料欄位、異常責任流程與保存期限
- [ ] 以實際使用量重新決定更新頻率與效能門檻

## 9. 變更管理規則

任何介面需求調整前，先確認下列問題，避免只改畫面卻破壞判定邏輯：

1. 這是顯示方式改變，還是點收規則改變？
2. 會不會讓進度、點收結果與資料品質再次混在一起？
3. 新增欄位來自新／舊版哪一種來源文件？缺值時要怎麼標示？
4. 是否影響來源文件開啟權限或資料保護？
5. 是否需要新增測試案例與 Demo 情境？

> 原則：能由資料規則、欄位驗證與系統提示防呆的問題，不長期依賴使用者記憶或口頭判斷。
